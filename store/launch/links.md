# Как считать отдачу каждого поста — без слежки

Задача: понять, сколько людей пришло в RuStore с каждого поста, и не ставить на сайт и в приложение ни счётчиков, ни cookie, ни аналитики. Приложение по-прежнему ничего о пользователе не знает. Считаем только две вещи:

1. **Переходы**: сколько раз нажали на короткую ссылку конкретного поста. Это видно на нашем сервере.
2. **Установки**: сколько установок в RuStore было в дни после поста по сравнению с обычными днями. Это видно в консоли RuStore.

## 1. Короткие ссылки

У каждого размещения своя ссылка, все они ведут на одну карточку в RuStore:

| Ссылка | Где |
|---|---|
| marginapp.ru/tg1 | пост 1 «Голосовые — в текст» |
| marginapp.ru/tg2 | пост 2 «Скажите — и дело на месте» |
| marginapp.ru/tg3 | пост 3 «Помнит, кто кому должен» |
| marginapp.ru/my | свой канал |
| marginapp.ru/habr | статья на Хабре |
| marginapp.ru/4pda | шапка темы на 4PDA |
| marginapp.ru/reel | профиль под роликом |

Если один пост покупается в двух каналах — дать каждому каналу свой номер (tg4, tg5…), иначе их не различить.

### Вариант А. Переадресация в .htaccess и подсчёт по журналу сервера

Самый простой: ни одной строки кода. Добавить в `.htaccess` сайта (`~/Desktop/Проекты/Margin-site/.htaccess`, после блока `IfModule mod_headers.c`):

```apache
# Short links for posts: each goes to the RuStore card; the server's access log counts them.
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteRule ^(tg[0-9]+|my|habr|4pda|reel)/?$ https://www.rustore.ru/catalog/app/ru.margin.app [R=302,L,NC]
</IfModule>
```

Почему 302, а не 301: браузеры запоминают 301 навсегда, и второй переход того же человека до сервера не дойдёт. К тому же 302 позволит потом поменять адрес назначения (например, на страницу сайта), не ломая старые посты.

**Журнал доступа.** Каждый переход — строка в журнале веб-сервера: `"GET /tg1 HTTP/1.1" 302`. В домашней папке на Beget журналов сейчас нет (проверено по SSH 19 окт: ни `~/logs`, ни `~/.logs`, в `~/marginapp.ru/` только `public_html`). Значит, их надо включить в панели управления Beget — в настройках сайта marginapp.ru, раздел с журналами (логами) доступа. Где именно этот переключатель и сколько дней Beget хранит журналы, я не проверял — посмотреть в панели или спросить поддержку Beget.

Когда журнал есть, подсчёт по меткам (путь к файлу подставить свой):

```bash
ssh beget-brus "grep -E '\"GET /(tg[0-9]+|my|habr|4pda|reel)/? ' ПУТЬ/К/access.log | grep -viE 'bot|preview|crawler|spider' | grep -oE 'GET /[a-z0-9]+' | sort | uniq -c"
```

По дням для одной метки:

```bash
ssh beget-brus "grep '\"GET /tg1' ПУТЬ/К/access.log | grep -viE 'bot|preview' | cut -d[ -f2 | cut -d: -f1 | sort | uniq -c"
```

Что важно про журнал:

- **Предпросмотр ссылок.** Когда пост выходит, Telegram сам один раз открывает ссылку, чтобы нарисовать карточку (в журнале — `TelegramBot (like TwitterBot)`). Так же делают ВКонтакте и другие. Фильтр `bot|preview` их убирает.
- **В журнале есть IP-адреса.** Мы их не выписываем, не храним отдельно и ни с чем не сопоставляем — считаем только число строк. Журнал ведёт хостинг и сам его удаляет через свой срок.

### Вариант Б. Свой счётчик без IP (если журналов нет или не хочется хранить IP)

Маленький PHP-файл, который записывает только дату и метку и сразу отправляет в RuStore. Ни IP, ни браузера, ни cookie.

`Margin-site/go.php`:

```php
<?php
// Counts a short link (date and label only — no IP, no browser, no cookie) and sends the visitor to RuStore.
$store = 'https://www.rustore.ru/catalog/app/ru.margin.app';
$c = isset($_GET['c']) ? strtolower($_GET['c']) : '';
$ua = isset($_SERVER['HTTP_USER_AGENT']) ? $_SERVER['HTTP_USER_AGENT'] : '';
if (preg_match('/^(tg[0-9]+|my|habr|4pda|reel)$/', $c) && !preg_match('/bot|preview|crawler|spider/i', $ua)) {
    $dir = dirname(__DIR__) . '/clicks';  // outside public_html: not reachable from the web
    if (!is_dir($dir)) @mkdir($dir, 0700);
    @file_put_contents($dir . '/clicks.csv', date('Y-m-d') . ';' . $c . "\n", FILE_APPEND | LOCK_EX);
}
header('Cache-Control: no-store');
header('Location: ' . $store, true, 302);
```

В `.htaccess` вместо правила из варианта А:

```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteRule ^(tg[0-9]+|my|habr|4pda|reel)/?$ go.php?c=$1 [L,NC,QSA]
</IfModule>
```

Подсчёт:

```bash
ssh beget-brus "sort ~/marginapp.ru/clicks/clicks.csv | uniq -c"
```

Код совместим и со старыми версиями PHP (на сервере в консоли 5.6, у сайта версия выбирается в панели). Перед заливкой проверить локально: `php -S localhost:8080` в папке сайта и открыть `localhost:8080/go.php?c=tg1`.

**Какой выбрать.** Если журналы в Beget включаются в два щелчка — вариант А, кода нет вообще. Вариант Б — если журналов нет, если они хранятся слишком мало или если хочется, чтобы на сервере не было даже IP-адресов переходов. Политику на сайте менять не нужно ни в одном варианте: она про приложение, а приложение по-прежнему ничего не отправляет. Для варианта А общая политика ИП Кобец про журналы сайта — проверить, что она это покрывает.

**Заливка.** Как обычно для marginapp.ru: только после вашего «да», перед этим архив `public_html` в `~/backups/` на сервере. Проверка после заливки: `curl -sI https://marginapp.ru/tg1` должен вернуть `302` и `location: https://www.rustore.ru/catalog/app/ru.margin.app`.

## 2. Что смотреть в консоли RuStore

В консоли разработчика RuStore у приложения есть статистика по дням. Названия пунктов сверить на месте; смотреть:

- **просмотры карточки** — сколько людей открыли страницу Margin в RuStore;
- **установки** — новые установки по дням;
- **конверсию из просмотра в установку** — если карточка смотрится, а не ставится, дело в карточке (скриншоты, описание), а не в посте;
- **удаления** — если после поста много удалений в первые дни, пришли не те люди или что-то не так с первым запуском (например, модель речи долго качается);
- **оценки и отзывы** — после каждого поста;
- **источники установок** — если в консоли есть разбивка по источникам или меткам ссылок, проверить, можно ли добавить метку в адрес переадресации. Если можно, установки по постам будут видны напрямую, без сравнения по дням.

## 3. Как сравнивать посты

Таблица на каждый пост (можно вести в любой таблице):

| Пост | Канал | Дата | Цена | Переходы | Установки за 3 дня | Обычно за 3 дня | Прирост | ₽ за переход | ₽ за установку |
|---|---|---|---|---|---|---|---|---|---|
| tg1 | | | | | | | | | |

- **Обычно за 3 дня** — среднее число установок за три дня по последней неделе без постов.
- **Прирост** = установки за 3 дня после поста − обычно за 3 дня.
- **₽ за установку** = цена поста / прирост.

Чтобы цифры были честными:

- ставить посты **не чаще одного в 3–4 дня**, иначе прирост установок не разделить между ними;
- переходы считаются точно, установки — только приблизительно: часть людей найдёт Margin поиском в RuStore, не нажимая ссылку;
- первые несколько постов — тест: сравнить три захода (tg1/tg2/tg3) в похожих каналах и дальше платить только за тот, что дал меньшую цену установки.

# Подпись: свой ключ в Play App Signing (PEPK)

Цель: Google Play должен подписывать Margin **тем же ключом `release.jks`**, что и APK в RuStore. Тогда подписи совпадают и человек может ставить обновления из любого магазина поверх установленного (если номер версии в магазине не меньше установленного).

Отпечаток ключа Margin (SHA-256), с ним сверяться в консоли:

```
E1:57:A5:48:A0:30:BF:70:94:A0:9C:2E:F8:00:2E:64:0E:D7:93:14:B6:D8:E0:6D:A1:E4:6C:1C:86:03:74:ED
```

Им подписаны и `releases/Margin-0.93.apk` (RuStore), и `releases/google-play/Margin-0.93-sdk36-draft.aab` (проверено `apksigner` и `keytool`). Псевдоним ключа в хранилище — `margin`.

## Главное предупреждение

Сделать это **до первой загрузки AAB в Play**. Если загрузить сборку, не выбрав свой ключ, Google создаст собственный ключ подписи — и подписи в Play и RuStore разойдутся навсегда для всех, кто поставит приложение из Play (переход между магазинами будет только через удаление с потерей данных).

## Шаги в Play Console

1. Создать приложение (`ru.margin.app` фиксируется первой загрузкой).
2. «Тестирование и выпуск» → «Закрытое тестирование» → «Создать выпуск». В блоке «Подписание приложений в Google Play» нажать **«Изменить ключ подписи приложения»** (Change app signing key) → **«Экспортировать и загрузить ключ из хранилища ключей Java»** (Export and upload a key from Java keystore).
   Тот же выбор есть в «Настройка → Целостность приложения → Подписание приложений», пока ничего не загружено.
3. Скачать с этой страницы `pepk.jar` и открытый ключ шифрования `encryption_public_key.pem` в папку вне git, например `archive/local/play-signing/` (папка `archive/local/` в `.gitignore`).
4. В Терминале, из папки проекта:

```bash
cd ~/Desktop/Проекты/Margin/archive/local/play-signing && /opt/homebrew/opt/openjdk@17/bin/java -jar pepk.jar --keystore=../../../release.jks --alias=margin --output=margin-app-signing-key.zip --include-cert --rsa-aes-encryption --encryption-key-path=encryption_public_key.pem
```

   PEPK спросит пароль хранилища и пароль ключа — они в `keystore.properties` (`storePassword`, `keyPassword`). Вводите их сами, в Терминале; в чат не вставлять. Хранилище PEPK только читает, `release.jks` не меняется.
5. Загрузить получившийся `margin-app-signing-key.zip` на ту же страницу консоли. Файл зашифрован открытым ключом Google — прочитать его может только Google.
6. **Ключ загрузки** (upload key) — на той же странице есть необязательный пункт «загрузить сертификат отдельного ключа загрузки». Рекомендую **пропустить**: тогда ключом загрузки остаётся тот же `release.jks`, и наш `bundleRelease` подходит как есть. Отдельный ключ загрузки чуть безопаснее (его, в отличие от ключа подписи, можно сбросить через поддержку Google при утере), но это второй ключ, который надо хранить и прописать в сборку; завести его можно и позже.
7. Сохранить. Затем загрузить AAB.
8. Проверить: «Настройка → Целостность приложения → Подписание приложений» → «Сертификат ключа подписи приложения» → SHA-256 должен совпасть с отпечатком выше.

## Что потом

- Каждая следующая версия для Play — тот же `bundleRelease` (AAB подписывается `release.jks` по `keystore.properties` автоматически).
- Для RuStore по-прежнему `assembleRelease` (APK). Одна версия — один номер (`versionCode`) в обоих магазинах.
- Копия `release.jks` и `keystore.properties` вне этого Mac обязательна (так и записано в CLAUDE.md): без них не обновить приложение ни в одном магазине. После загрузки в Play у Google будет копия ключа подписи, но RuStore-обновления всё равно подписываются локально.
- `pepk.jar`, `.pem` и `.zip` после загрузки можно удалить.
